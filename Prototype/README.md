# In Game Surface · прототип 01

Прототип рекламы на поверхностях в игровом мире «Стажёра». Независимая локальная демонстрация: свой сервер, тестовые кампании и пиксели. API Adlook не подключается.

В комплекте `creative/IGS-demo-15s.mp4`: оригинальный анимационный креатив **15 секунд, 1280×720, 30 fps, H.264, без звука**. Это видео для размещения на игровой поверхности. Для записи геймплея добавлена кнопка MP4 в редакторе; сама запись пока не выполнена. Креатив не прошёл сравнение с присланными IBV / pre-roll / fly-roll: их видеосодержимое не удалось получить в рабочую среду.

## Быстрый запуск

1. Открой корень проекта `stazher-main` в Unity **6000.6.2f1**. Дождись импорта пакетов и ресурсов.
2. Запусти локальный сервер из папки `Prototype`:

   macOS:

   ```sh
   python3 -m venv .venv
   .venv/bin/pip install -r requirements.txt
   .venv/bin/python server.py
   ```

   Windows PowerShell:

   ```powershell
   py -3 -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe server.py
   ```

   После установки зависимостей можно запускать `start-mac.command` или `start-windows.bat`. Для новой установки подходит Python 3.11/3.12. Сервер и тесты также проверены на Python 3.9 с указанными версиями библиотек.

3. Открой <http://127.0.0.1:8765>. На чистой базе видео IGS уже назначено трём поверхностям.
4. Для обычной игры выбери **In Game Surface → Открыть игру с рекламой**, затем нажми **Play**. Откроется исходная игра: меню, персонаж, ходьба, задания, офис и выход в город. Два экрана добавляются в офис сразу, городской щит — после создания города. В меню, паузе, диалогах и IDE показ рекламы не учитывается.
5. Для проверки рекламы отдельно выбери **In Game Surface → Открыть демонстрацию**, затем **Play**. В сцене `IGSDemo` доступны переходы между тремя местами, перекрытие, поворот камеры, счётчики и экспорт. Перед сменой режима останови Play.

В Unity Hub: **Projects → Add → Add project from disk** и выбери корень `stazher-main` (папку с `Assets`, `Packages`, `ProjectSettings`). Затем открой проект в Unity 6000.6.2f1. Сам Hub не запускает игру — Play находится в редакторе.

13 ноября 2026 года отдельная демонстрация запущена в Unity на macOS: MP4 воспроизводился на игровой поверхности, сервер принял настоящие GET-пиксели, включая complete. Исправлена ошибка создания демосцены рядом с несохранённой пустой сценой. Новое подключение к обычной игре и запись MP4 проверены компиляцией; полный прогон этих двух новых функций ещё предстоит.

## Что показать руководителю

| Действие | Ожидаемый результат |
|---|---|
| Посмотреть на экран | MP4 воспроизводится на поверхности, появляются VAST Impression и start |
| Смотреть 2 секунды | Отдельно засчитывается видимый показ по демонстрационному правилу |
| Досмотреть 15 секунд | Приходят firstQuartile, midpoint, thirdQuartile, complete |
| Нажать «Перекрыть» | Стена закрывает экран, видео и время видимости останавливаются |
| Отвернуться / свернуть окно / пауза | Видео и время видимости останавливаются |
| Убрать стену и продолжить | Видео продолжается, повторные события этого сеанса не увеличивают счётчик |
| Загрузить другой MP4 в панели и назначить | Креатив меняется без пересборки игры |
| Нажать «Новый сеанс» | Новые тестовые события, ролик начинается заново |

В обычной игре: WASD — ходьба, Shift — бег, Space — прыжок, мышь — обзор, Esc — пауза.

Управление свободной камерой в отдельной демонстрации: удерживать правую кнопку мыши, WASD, Q/E вверх-вниз, Shift ускорение. Esc — пауза. Это отдельный режим демонстрации на базе окружения игры; он не запускает карьеру, Docker и сохранения игрового прогресса.

## Запись демонстрации

В редакторе, в режиме `IGSDemo`, нажми **«Записать демонстрацию · MP4»** и оставь окно Game активным. Сценарий длится 45 секунд: кофе → перекрытие → поворот → пауза → экран в офисе → городской щит. Записывается собственный кадр игры, без рабочего стола и микрофона. Размер — до 1920 пикселей по ширине с сохранением пропорций. Временные метки соответствуют реальному ходу игры.

Результат: `Prototype/recordings/IGS-gameplay-<дата>.mp4` и журнал показателей `.jsonl`. Не меняй размер Game View во время записи. Кнопка доступна только в редакторе; MP4-экспорт ещё нужно проверить на целевой машине.

## VAST и пиксели

Последовательность: **конфигурация → VAST XML → локальный MP4 → VideoPlayer → RenderTexture → поверхность**. Unity сама выполняет GET-запросы на адреса tracking из XML. Видео не исполняет JavaScript и не содержит пиксели внутри MP4.

Локальный VAST URL: `http://127.0.0.1:8765/vast/office_coffee.xml?session=<UUID>`. Панель формирует ссылку кнопкой «Открыть VAST XML». Параметр `creative` позволяет отвергнуть устаревшее назначение.

Поддержано ограниченное подмножество VAST 4.3: **один InLine, один Linear, progressive MP4**, Impression, creativeView, start, firstQuartile, midpoint, thirdQuartile, complete, Error; макросы CACHEBUSTING и ERRORCODE. Парсер учитывает XML namespace, запрещает DTD и исполняемые MediaFile.

Для прототипа разрешены только адреса `127.0.0.1:8765`. Произвольный внешний VAST, Wrapper-цепочки, ad pods, VPAID, SIMID, OMID и ClickThrough пока не реализованы. **Это не универсальный VAST SDK и не подтверждённая интеграция Adlook.** Следующая интеграция потребует согласованного тестового тега, политики адресов и проверки поведения рекламного сервера. VPAID для обычного MP4 и пикселей не требуется.

### Разделение измерений

- **loaded:** файл подготовлен и декодирован первый кадр; показ не засчитывается.
- **VAST Impression / start:** следующий видеокадр готов к отображению, окно активно, поверхность проходит проверку видимости. Это оценка на стороне плеера, без независимой верификации рендера.
- **Видимый показ в отчёте:** 2 секунды непрерывно, ≥50% контрольных точек поверхности видно, площадь поверхности ≥1% кадра, угол ≤60°. Один показ на место/креатив/сеанс.
- **Квартили и complete:** реальная позиция VideoPlayer; повторные циклы не создают новые события этого сеанса.
- **Доставка пикселя:** HTTP 200 и запись в таблице `pixels`. События внутреннего журнала сами по себе не создают строку в этой таблице.

Перекрытия оцениваются лучами по сетке 5×5. Частично пересекающая ближнюю плоскость поверхность консервативно исключается. Это демонстрационная методика, не сертифицированный измеритель и не основание для биллинга. Внешнюю проверку viewability в проект не добавляли.

Пиксели имеют идентификатор ответа VAST; локальный сервер устраняет дубли `(ad, kind)`. Клиент делает до трёх попыток доставки и хранит очередь на диске. После трёх неудач показывает ошибку; бесконечных повторов нет. Внешний рекламный сервер может иметь другие правила повторов — перед интеграцией их нужно согласовать.

## Хранение и отчёты

- `Prototype/data/`: SQLite, загруженные медиа, локальная статистика. Каталог исключён из git и архива исходников.
- `Application.persistentDataPath/InGameSurface`: кэш медиа/конфигурации, очередь событий и пикселей, журнал `events.jsonl`.
- «Экспорт CSV» в игре выгружает события клиента; «Скачать CSV» в браузере — сводный отчёт локального сервера. Полученные пиксели доступны в панели и `/api/pixels`.
- Переход в браузер останавливает видимость в игре, поскольку окно теряет фокус. Для показа на встрече удобно использовать два монитора и возвращать фокус в игру.

## Сборка

Меню **In Game Surface → Собрать демо для macOS / Windows**. Нужен установленный модуль целевой платформы в Unity Hub. Результаты: `Builds/IGS-Mac/In Game Surface.app` или `Builds/IGS-Windows/InGameSurface.exe`. Сервер запускается отдельно на том же компьютере.

## Проверки

- 12 интеграционных тестов сервера: назначения, события/дубли, ошибки, MP4-загрузка, VAST, GET-пиксели, блокировка неизвестных пикселей, отключение кампании.
- 10 сценариев настоящего C# VAST-парсера: медиа/события, namespace, недопустимые URL, DTD, VPAID, Wrapper, макросы.
- 5 сценариев C# измерения времени: непрерывность, прерывание, дубли, длинный кадр, потеря фокуса.
- C# модуль и игровые/редакторские исходники проверены отдельной компиляцией с библиотеками установленного Unity и его шаблона. Шаблонные зависимости не заменяют фактический импорт manifest.
- JavaScript панели проверен синтаксически; визуальная работа панели в браузере не проверялась.
- MP4 проверен декодированием; проверены кадры на 1,5 / 5 / 9,5 / 13 секунде, формат и длительность.
- Unity Play Mode на macOS: отдельная сцена, воспроизведение MP4, реальные полученные сервером VAST-пиксели включая complete.
- Последние изменения (обычная игра с рекламой, запись MP4, масштаб панели) прошли отдельную компиляцию C# с библиотеками Unity 6000.6.2f1.
- **Не выполнены:** полный прогон рекламы в обычной игре, тесты физики внутри Unity, сборка исполняемого приложения, запись и проверка MP4 геймплея.

Тесты сервера: `python3 -m unittest discover -s Prototype -p test_server.py` из корня. Unity-тесты находятся в `Assets/InGameSurface/Tests/Editor/`. Два автономных C# harness-файла проверяют реальные классы без игрового движка.

Повторная генерация ролика на macOS: `swift Prototype/render_creative.swift result.mp4`. Если системный H.264 encoder недоступен: `swift Prototype/render_creative.swift --raw | ffmpeg -f rawvideo -pixel_format bgra -video_size 1280x720 -framerate 30 -i pipe:0 -c:v libx264 -crf 19 -pix_fmt yuv420p -movflags +faststart -an result.mp4`. FFmpeg не входит в архив.

Основа протокола: [IAB VAST 4.3](https://github.com/InteractiveAdvertisingBureau/VAST4.x/blob/main/4.3.md). Событие Unity: [VideoPlayer.frameReady](https://docs.unity.com/en-us/engine/6000.6/script-reference/unityengine/video/videoplayer/frameready).
