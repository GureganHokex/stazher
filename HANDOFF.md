# Хендоф: «Стажёр» (Codezilla Games)

Состояние на 24.09.2026 (вечер). Документ для новой сессии Claude: что сделано, где что лежит, как устроено, что дальше.

## 1. Что это за проект

Игра на Unity 6 (6000.6.2f1, URP 17.6, Input System 1.20): симулятор стажёра в офисе «Кодзилла Софт», который учит Python. Игрок ходит по 3D-офису, садится за компьютер, решает тикеты в игровой IDE с отладчиком, получает монеты и звания (Стажёр → Junior → Junior+).

Визуальный референс — How to Fish (Dazed Games): low-poly, плоское затенение, долговязые нелепые персонажи с голой головой-«фасолью» и большими глазами, матовые приглушённые цвета, жёсткое солнце. Свои персонажи — офисные, не копия рыбака.

Пользователь пишет по-русски, отвечать по-русски.

## 3. Как устроено (важные решения)

- Игра собирается сама в любой сцене через `[RuntimeInitializeOnLoadMethod]` — достаточно нажать Play.
- Если есть `Resources/Models/Office`, офис грузится из FBX (`ImportedOffice.Build`), иначе строится кодом (`OfficeBuilder`).
- **Офис** экспортирован с `bake_space_transform=True` (иерархии нет, так можно) → в Unity корень повёрнут на 180° по Y.
- **Персонажи v3**: одна сглаженная сетка тела (кольцевой каркас + Catmull-Clark) со скинингом на кости, одежда — оболочки поверх тела, детали лица жёстко привязаны к `Head`/`LidL/R`. N-угольники триангулируются при сборке (иначе Unity выкидывает самопересекающиеся полигоны). Экспорт FBX: `FBX_SCALE_ALL`, без leaf bones, без `bake_space_transform`, `use_armature_deform_only=False`.
- В Unity `CharacterAnim.BuildImported`:
  1. ставит модель на ноги по положению головы и носа;
  2. пересобирает кости в осях персонажа (`NormalizeRig`), меши сохраняют положение в мире;
  3. `BindSkins`: переносит SkinnedMeshRenderer'ы в риг и вешает исходные кости под нормализованные узлы (bindposes остаются верными).
  В настройках импорта выключено Preserve Hierarchy, поэтому узел `Root` «съедается» — код это учитывает.
- **Кости** (пустышки): `Root, Hips, HipL/R, KneeL/R, Torso, ShoulderL/R, ElbowL/R, Neck, Head, LidL/R, Acc_*, Mouth_<id>`. L — левая сторона персонажа.
- **Одежда:** части называются `Top_<id>__*`, `Bottom_<id>__*`, `Shoes_<id>__*`. Костюмы: `classic, junior, backend, frontend, teamlead, devops, designer, qa, hackathon`. У стажёра в FBX все 9, у коллег — по одному.
- **Рты:** `smile, grin, flat, o, frown, smirk`. **Аксессуары:** `Acc_Glasses, Acc_Headphones, Acc_Cap, Acc_Beanie, Acc_Crown`.
- **Перекраска** по префиксам материалов: `lp_skin_, lp_sock_, lp_shirt_, lp_pants_, lp_boots_, lp_tie_`. Индекс цвета `-1` = «как у костюма».
- `Appearance`: `skin, outfit, emotion, topColor, pants, shoes, tie, accessory` (+ старые поля для процедурного персонажа). `Catalog`: `OutfitIds/Names/Price`, `EmotionNames` и таблицы `EmoMouth/Tilt/Raise/Lid/Pupil`.
- **Эмоции** (8): спокойный, радость, восторг, удивление, грусть, злость, хитрый, сонный. Веко — купол над глазом, закрывается поворотом `LidL/R` на +165° по X. Реакции: `React(2)` — восторг после сдачи задачи, `React(4)` — грусть при упавшем тесте, Гена `React(1)` при разговоре.
- **Посадка:** детали кресла игрока собраны в объект `PlayerChair` (`refs.chairObj`). Кат-сцены `SitDown`/`StandUp` в `GameRoot`: подойти сбоку → отодвинуть кресло → сесть с «плюх» → подкатиться → камера на монитор.
- **IDE на мониторе (новая):** `IdeScreen` рисует панель UI Toolkit в RenderTexture (высота 1000 px, ширина по пропорциям экрана, сейчас 1776×1000) через `PanelSettings.targetTexture`. Родной ввод UI Toolkit выключен; клики и клавиши приходят из `OnGUI` игры: `GameRoot.ScreenToMonitor` пускает луч из камеры в плоскость экрана и переводит в координаты панели, дальше `panel.Pick` + свои `Btn`. Когда стажёр не за компьютером, IDE всё равно видна на мониторе в офисе.
- **Экраны мониторов:** у `*__MonScreen` из `Office.fbx` нормаль смотрит внутрь корпуса (их не было видно вообще). `ModelLib.FrontQuad` ставит свой прямоугольник на 3 мм перед корпусом лицом к креслу/наружу, исходный рендерер выключает, стикеры `Sticky*` сдвигает на рамку. У коллег на нём прокручивается код, у игрока — IDE.
- **Сообщения игры** (награды, повышение, новая задача), пока игрок за компьютером, показываются уведомлениями внутри IDE (`IdeScreen.GameNotice`), а не жёлтыми тостами.
- **Меню, пауза, настройки, HUD** — `GameUi`: отдельный UIDocument поверх экрана (ScaleWithScreenSize, эталон 1920×1080 по высоте, масштаб интерфейса из настроек меняет эталон). Ввод родной для UI Toolkit (мышь), Esc ловит `GameRoot` и зовёт `ui.Back()` (закрыть настройки / страницу новой игры), иначе продолжает игру. Какие слои видны, `GameUi.Tick` решает по `GameRoot.CurMode`. Если `GameUi` не создался — работают старые IMGUI `DrawMenu/DrawHud/DrawPause`. Диалоги и гардероб пока остаются на IMGUI.
- **Настройки графики URP** применяются в `Intern.Look.UrpLook.Configure` (вызов по имени через `Type.GetType("Intern.Look.UrpLook, Intern.URP")` — сборки не ссылаются друг на друга). В редакторе после выхода из Play `UrpLook` возвращает ассету конвейера исходные значения, чтобы не пачкать проект.
- **Материалы моделей** переводятся в матовый URP Lit (`ModelLib.Convert`); экраны получают текстуры из `Resources/Textures`.
- В Unity у пользователя включены Enter Play Mode Options без перезагрузки домена и сцены.

## 4. Как работал Claude (рабочий процесс)

- Сессия Cowork связана с компьютером пользователя (папка `C:\Users\VINACUR\codezilla-games`). `device_bash` на Windows после обновления не работал — всё делалось через `device_stage_files` / `device_commit_files` и Blender MCP.
- Компиляция в песочнице: `mcs` против **настоящих** сборок Unity, скопированных в `Library/ClaudeRefs/` (UnityEngine.*Module.dll, netstandard.dll) + `Library/ScriptAssemblies/Unity.InputSystem.dll`. Для mcs в стилях UI Toolkit нужны float-литералы (`style.flexShrink = 0f`).
- Запись в проект: построчный патч (difflib) с md5 до и после → `device_commit_files` в `Temp/claude_patch_NNN.py` под **новым** именем (повторная запись по тому же пути отдаёт старую копию!) → `exec` в Blender с проверкой md5 патча. После патча в Unity: Assets → Refresh.
- **Лог игры в редакторе** дублируется в `Temp/intern_log.txt` (`Application.logMessageReceived`, только редактор) — удобно читать снаружи. `Editor.log` огромный (>1 ГБ) и мог быть заменён вторым запуском Unity.
- **Тестовые клавиши (только редактор):** F8 — сразу сесть за компьютер, F6 — встать из-за компьютера, F7 — снимок текстуры IDE и состояния в `Temp/ide_dump.png/.txt`, F4 — то же, что Esc (Esc через удалённое управление не доходит).
- Unity управляется через computer use (разрешён только Unity). Не запускать Unity через open_application — стартует второй экземпляр. Esc через computer use до игры не доходит; поверх правого верхнего угла экрана может висеть невидимое на скриншотах окно превью Claude — клики туда не попадают в Unity.
- Скриншоты Blender на Windows работают, только когда окно Blender **на переднем плане** (иначе приходят чёрными). Запасной путь — рендер в JPEG и передача в base64 (дорого).
- Коммит и пуш — через `git` из Python в Blender (`subprocess`, `GIT_TERMINAL_PROMPT=0`).
- Вспомогательные функции Blender хранятся в текст-блоках внутри `.blend`. После перезапуска Blender их нужно заново выполнить: `exec(bpy.data.texts["intern_character_v2.py"].as_string())`.
